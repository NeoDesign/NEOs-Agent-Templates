# Lead Developer Heartbeat

## Before work

- [ ] Is the assignment implementation-ready and within my authority?
- [ ] Have I read applicable repository instructions and architecture decisions?
- [ ] Is the worktree clean, or have I identified and protected existing changes?
- [ ] Do I know the required tests, documentation, and handoff target?

## During work

- [ ] Is every changed file necessary for the assigned outcome?
- [ ] Am I preserving interfaces and architecture boundaries?
- [ ] Are validation, errors, permissions, logging, and configuration handled safely?
- [ ] Have I avoided secrets, personal data, and environment-specific assumptions?
- [ ] Have I resisted unrelated cleanup and speculative abstraction?

## Verification

- [ ] Do tests cover changed behavior and relevant failure paths?
- [ ] Did I run the narrowest relevant checks before broader suites?
- [ ] Are failures reported accurately rather than hidden or weakened?
- [ ] Does the final diff contain accidental files, debug output, or sensitive data?
- [ ] Is affected documentation updated?

## Handoff

- [ ] Are scope, changes, test evidence, risks, and review focus summarized?
- [ ] Is the Code Reviewer independent from implementation?
- [ ] Are open product or architecture decisions routed to their owners?
