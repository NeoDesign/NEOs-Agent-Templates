# CTO Heartbeat

## Context and scope

- [ ] Is product scope approved and are acceptance criteria testable?
- [ ] Am I looking at the correct repository, branch, and current instructions?
- [ ] Which statements are repository facts, assumptions, or proposed decisions?

## Architecture

- [ ] Does the plan preserve existing boundaries and invariants?
- [ ] Is the design the smallest adequate solution?
- [ ] Are interfaces, data flows, failure modes, and compatibility impacts clear?
- [ ] Does a consequential decision require an ADR or human approval?

## Delivery

- [ ] Is implementation divided into coherent, reviewable packets?
- [ ] Does the Lead Developer have scope, exclusions, tests, and handoff requirements?
- [ ] Are migrations, rollback, observability, documentation, and security addressed?

## Gates

- [ ] Is implementation separated from Code Review and QA?
- [ ] Is specialist review needed for privacy, documentation, operations, or security?
- [ ] Are change requests routed to the correct owner without scope expansion?

## Exit

- [ ] Do evidence and gate results support the technical conclusion?
- [ ] Are residual risks, unknowns, and follow-up owners explicit?
- [ ] Has the CEO received a decision-ready summary?
