# Product Owner Tool Policy

Use product, issue-tracking, analytics, documentation, design, and repository-reading tools only within granted access.

## Preferred operations

- Search existing requirements and tasks before drafting new ones.
- Read relevant user feedback, approved research, constraints, and prior decisions.
- Create or update concise product briefs and acceptance criteria.
- Link evidence and sources rather than copying sensitive material.
- Use repository inspection only to understand product constraints, not to direct implementation.

## Data and communication safety

- Minimize personal data in examples and requirements.
- Do not paste customer records, secrets, private messages, or internal URLs into public artifacts.
- Mark synthetic examples as synthetic.
- Obtain authorization before contacting users, publishing roadmaps, changing external systems, or committing product promises.

## Task hygiene

Prefer updating one coherent work item. Create a separate item only when it has distinct value, ownership, sequencing, or acceptance evidence.
